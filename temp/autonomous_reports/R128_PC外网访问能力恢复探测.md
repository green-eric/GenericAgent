## 二、根因分析

### 🔴 核心问题：Clash Verge 代理端口未启动

| 检查项 | 结果 |
|--------|------|
| Clash进程 | ✅ clash-verge.exe(PID 9668) + service(PID 3964) |
| 监听端口 | ⚠️ 仅 127.0.0.1:33331（内部通信端口） |
| 标准代理端口 | ❌ 7890/7891/7892/1080/1081/8080 全部未监听 |
| 33331端口功能 | ❌ CONNECT测试返回404（非代理端口） |
| WinHTTP代理 | ❌ "直接访问(没有代理服务器)" |
| 系统环境变量 | ❌ HTTP_PROXY/HTTPS_PROXY/all_proxy 均未设置 |
| TUN适配器 | ❌ 未找到 |

### 根因结论

Clash Verge 进程在运行但**代理服务未正确启动**。可能原因：
1. Clash Verge 服务未安装（sc query返回"指定的服务未安装"）
2. TUN模式未启用或适配器缺失
3. 配置文件中代理节点全部不可用
4. Clash Verge版本升级后服务注册丢失

---

## 三、修复方案（按优先级）

### 方案A：重启Clash Verge服务（最简单）

1. 关闭Clash Verge
2. 重新以管理员身份运行
3. 检查系统托盘图标是否显示"代理已连接"
4. 验证 `netstat -ano | findstr 7890` 有监听

### 方案B：重新安装Clash Verge服务

```powershell
# 以管理员身份运行
# 找到Clash Verge安装目录，重新安装服务
clash-verge-service.exe install
clash-verge-service.exe start
```

### 方案C：手动设置系统代理

如果Clash端口恢复但系统代理未自动设置：
```powershell
# 手动设置系统代理（假设Clash HTTP代理在7890）
netsh winhttp set proxy 127.0.0.1:7890 "<local>"
```

### 方案D：浏览器级别代理配置

浏览器设置 SOCKS5代理 `127.0.0.1:1080` 或 HTTP代理 `127.0.0.1:7890`
