# 定时任务调度器健康检查

## 发现的问题

### 1. 任务每 2 分钟重复触发（高频日志）
- `scoresys_check_score_done` 每 2 分钟触发一次（日志 11:29~11:41 共 7 次）
- 配置应为 `repeat=every_30m`，冷却逻辑本身正确（_parse_cooldown 返回 30 分钟）
- 根因：任务从未成功执行，`last_run=None`，冷却检查被跳过

### 2. disabled 任务仍在触发
- `scoresys_daily_backtest.json` 配置 `enabled=false`
- 但 5/22 日志显示该任务每 2 分钟触发（共 114 次 TRIGGER）
- 说明 `enabled` 检查在 5/22 时未生效（可能是旧版 scheduler.py 的 bug）

### 3. done 目录为空
- `sche_tasks/done/` 目录存在但 0 个文件
- 所有任务 `last_run=None`，从未成功执行过
- 调度器正确生成了 prompt 并 return，但 agentmain 未消费结果

### 4. 调度器进程状态
- `reflect/scheduler.py` 通过端口 45762 单例运行
- 日志最后更新：2026-05-24 11:41（活跃）

## 根因结论

**调度器本身逻辑基本正确**，核心问题是：
1. 调度器 return 的 prompt 未被 agentmain 消费执行 → 任务从未实际运行
2. 没有 done 文件 → last_run 永远为 None → 冷却机制失效 → 每 INTERVAL(120s) 重复触发

## 建议修复方向

1. **agentmain 消费逻辑**：确保 agentmain 处理 check() 返回的 prompt 并执行任务
2. **done 文件写入**：任务执行成功后必须写入 `done/` 目录
3. **enabled 检查**：确认当前 scheduler.py 版本已修复 enabled=false 跳过逻辑
4. **日志优化**：高频重复触发时增加去重日志
