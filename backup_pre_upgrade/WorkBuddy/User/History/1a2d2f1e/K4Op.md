# A股智能选股分析系统 V3.9.2 逻辑文档

<!-- 文档生成时间：2026-04-25 | 对应版本：V3.9.2 -->

## 1. 系统概述
本系统通过 NeoData 自然语言金融数据 API 获取 A 股最新财务报告，自动解析关键
指标与行业分类，基于行业内百分位评分生成 A~E 五级评级，输出 Excel 报告和
JSON 数据。

### V3.9.2 核心特性：

- **统一目录管理**：所有输出文件自动加上时间戳，防止覆盖
- **SQLite 缓存增量更新**：首次全量获取，以后每天仅更新过期或缺失的股票；批量写入
- **多报告期支持**：财务数据按报告期（年报/一季报/半年报/三季报）存储，支持报告期时间标识
- **智能缓存策略**：年报缓存时效考虑披露截止日（次年4月30日），避免季报空窗期无意义刷新
- **双重数据提取**：优先从 API 结构化字段提取指标，失败时回退文本解析
- **灵活行业映射**：行业映射表完全外部化，通过 industry_map.json 加载完整映射（约3000条），同时内置最小兜底表（仅100条）作为后备，易于维护和更新
- **日志管理**：日志轮转（RotatingFileHandler），限制日志文件大小，防止无限增长
- **超时保护**：全局超时保护，超时后真正取消未完成任务 (shutdown(wait=False, cancel_futures=True))
- **错误追踪**：新增"获取失败股票"工作表，便于定位数据缺失
- **内置测试**：内置自测模式，支持 --test 参数验证解析器
- **性能优化**：命令行可调整线程数 (--workers)，优化 API 请求速度

## 3. 核心模块说明
### 3.1 配置管理（Config 类）
    所有参数集中管理，支持命令行修改，包括路径、并发数、API 超时、缓存有效期、
    评分权重等。

3.2 行业映射文件加载
    - 优先加载工作目录下的 industry_map.json（可由原脚本内置字典导出）。
    - 加载失败或文件缺失时，使用内置最小兜底表 _FALLBACK_INDUSTRY_MAP
      （仅 100 条），并记录警告日志。
    - 外部文件便于持续维护和在线更新（可通过 URL 覆盖）。

3.3 API 调用（run_neodata）
    调用 NeoData 查询脚本，自动指数退避重试，处理输出干扰和 JSON 解析错误。
    增强保护：检查脚本文件是否存在，捕获 FileNotFoundError，避免程序崩溃。

3.4 文本解析与结构化提取
    - FinancialReportParser：按日期分割文本，识别报告类型，提取百分比和绝对值。
    - 优先从 API 数据中的 structured 字段提取指标，失败时回退到文本解析。
    - 缺失指标记录到日志，便于回溯补充正则模式。

3.5 行业分类引擎（六级顺序）
    优先级  策略                说明
    -----------------------------------------------------------
    1       文本提取            API 返回内容中直接提取
    2       映射表              内置最小兜底表或外部完整映射文件
    3       二级→一级反查       通过二级行业名称反推
    4       名称关键词推断       股票简称中的行业词（如"医药"、"银行"）
    5       轻量 API 补调       对仍未分类的股票发起简洁查询
    6       代码前缀推断       仅兜底使用（如 600→银行）

3.6 评分模型
    (1) 百分位计算
        - 有明确行业且样本 ≥5：按行业内百分位
        - 不足或未分类：全市场百分位，得分 × 0.95

    (2) 四维加权
        盈利能力 = 0.4×ROE% + 0.3×毛利率% + 0.3×净利率%
        成长性   = 0.4×营收同比% + 0.6×净利润同比%
        现金流   = 经营现金流/净利润%
        偿债风险 = 资产负债率%（越低越好）

        总评分 = 0.35×盈利 + 0.30×成长 + 0.15×现金流 + 0.20×偿债

    (3) 特殊惩罚：净利润 < 0 且经营现金流净额 < 0 → 总分 ≤ 15

    (4) 数据完整度处理：低完整度总分 × 0.9，标记置信度为"低"

    (5) 评级标准
        分数区间    评级
        ≥ 75        A
        ≥ 55        B
        ≥ 40        C
        ≥ 25        D
        其他         E

3.7 异常日志与失败收集
    全局记录失败详情，写入 Excel"异常日志"，收集完全失败股票到"获取失败股票"表。

4. 增量缓存机制
---------------
4.1 数据库结构（SQLite）
    - stocks 表：代码、名称、行业、更新时间
    - financial_reports 表：联合主键 (ts_code, report_date, report_type)，
      每条记录对应一个报告期，存储所有解析指标及 last_update

4.2 缓存有效期（含披露截止日保护）
    - 年报：超过 400 天且已过次年 4 月 30 日 → 需更新；否则暂不更新
    - 季报/半年报：超过 100 天 → 需更新

4.3 每日运行流程
    1) 加载股票列表，连接 DB
    2) 判断每只股票是否需要刷新（should_refresh）
    3) 不需刷新：从缓存组合数据；需刷新：并发获取，批量写入 DB
    4) 合并，行业分类，统计，评分，生成报告

  └── 股票分析数据_*.json       # JSON（时间戳）

6. 命令行用法
-------------
  python stock_analyzer.py --base-dir ./workplace --stock-file xuan.txt --workers 8

  主要参数：
  --base-dir            工作目录（默认脚本所在目录）
  --stock-file          股票列表文件
  --workers             线程数（默认 8）
  --force-refresh       忽略缓存全量更新
  --timeout             全局超时秒（默认 3600，0 不限）
  --no-retry-failed     禁用失败补采
  --no-industry-patch   禁用行业 API 补调
  --test                运行内置自测并退出

8. 注意事项
-----------
- 首次全量获取时间长，后续每日运行仅更新少数股票，数分钟内完成。
- 若需完整行业映射，务必在同目录下放置 industry_map.json（可从旧版脚本导出），
  否则分类准确率将下降。
- 若 API 大面积返回空，系统自动暂停后重试，异常均记录在日志和 Excel 中。
- 低置信度股票建议人工复核。
- 日志使用 RotatingFileHandler，确保长期运行不会无限增长。

9. 自测模式
-----------
  执行 python stock_analyzer.py --test 将运行内置解析器自测，验证财务指标
  提取正确性。通过后输出"自测通过，解析器工作正常。"
