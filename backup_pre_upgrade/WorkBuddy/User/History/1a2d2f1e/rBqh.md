# A股智能选股分析系统 V3.9 逻辑文档

---

## 1. 系统概述

本系统通过 NeoData 自然语言金融数据 API 获取 A 股最新财务报告，自动解析关键指标与行业分类，基于行业内百分位评分生成 A~E 五级评级，输出 Excel 报告和 JSON 数据。

**V3.9 核心特性：**

- 统一目录管理，所有输出文件自动加上时间戳，防止覆盖。
- SQLite 缓存增量更新：首次全量获取，以后每天仅更新过期或缺失的股票；批量写入。
- 财务数据按报告期（年报/一季报/半年报/三季报）存储，支持报告期时间标识。
- 年报缓存时效考虑披露截止日（次年4月30日），避免季报空窗期无意义刷新。
- 结构化数据提取优先：尝试从 API 结构化字段提取指标，失败时回退到文本解析。
- 解析失败日志：关键指标缺失时记录原始文本片段到日志，便于回溯补充正则模式。
- 行业六级兜底覆盖率 >95%，支持通过 `--industry-map-url` 在线更新映射表。
- 评分模型优化：低完整度仅打折，不强制压级，增加置信度标记。
- 全局超时保护，可设置的运行时间上限。
- 新增"获取失败股票"工作表，便于定位数据缺失。
- 日志轮转（RotatingFileHandler），限制日志文件大小，防止无限增大。
- 内置自测模式，支持 `--test` 参数验证解析器。
- 命令行可调整提交间隔（`--delay`）和线程数（`--workers`），优化 API 请求速度。

```
股票列表文件 → 主程序 → 加载配置与数据库
                              |
                        [SQLite 缓存]
                              |
                        需要更新？
                       /          \
             是（从API获取）   否（从缓存加载）
                       \          /

                              |

                              |
                        构建行业统计
                              |
                        计算评分与评级（含置信度）
                              |
                        生成 Excel 报告和 JSON
```

## 3. 核心模块说明

### 3.1 配置管理（Config 类）

所有参数集中管理，支持命令行修改，包括路径、并发数、API 超时、缓存有效期、评分权重等。

### 3.2 API 调用（run_neodata）

调用 NeoData 查询脚本，自动指数退避重试，处理输出干扰和 JSON 解析错误。

### 3.3 文本解析与结构化提取

- **FinancialReportParser**：按日期分割文本，识别报告类型，提取百分比和绝对值。
- **extract_financials_from_structured**：优先从 API 数据中的 `structured` 字段提取指标。
- **缺失指标记录**：`_log_missing_indicators` 输出警告和文本片段。

### 3.4 行业分类引擎（多级顺序）

| 优先级 | 策略 | 说明 |
|:---:|---|---|
| 1 | 文本提取 | API 返回内容中直接提取 |
| 2 | 内置/外部映射表 | 内置 3000+ 条，或外部 `industry_map.json`，或在线 URL 下载 |
| 3 | 二级→一级反查 | 通过二级行业名称反推 |
| 4 | 名称关键词推断 | 股票简称中的行业词（如"医药"、"银行"） |
| 5 | 轻量 API 补调 | 对仍未分类的股票发起简洁查询 |
| 6 | 代码前缀推断 | 仅兜底使用（如 600→银行） |

### 3.5 评分模型

**(1) 百分位计算**

- 有明确行业且样本 ≥5：按行业内百分位
- 不足或未分类：全市场百分位，得分 × 0.95

**(2) 四维加权**

```
盈利能力 = 0.4×ROE% + 0.3×毛利率% + 0.3×净利率%
成长性   = 0.4×营收同比% + 0.6×净利润同比%
现金流   = 经营现金流/净利润%
偿债风险 = 资产负债率%（越低越好）

总评分 = 0.35×盈利 + 0.30×成长 + 0.15×现金流 + 0.20×偿债
```

**(3) 特殊惩罚**：净利润 < 0 且经营现金流净额 < 0 → 总分 ≤ 15

**(4) 数据完整度处理**：低完整度总分 × 0.9，标记置信度为"低"

**(5) 评级标准**

| 分数区间 | 评级 |
|:---:|:---:|
| ≥ 75 | A |
| ≥ 55 | B |
| ≥ 40 | C |
| ≥ 25 | D |
| 其他 | E |

### 3.6 异常日志与失败收集

全局记录失败详情，写入 Excel"异常日志"，收集完全失败股票到"获取失败股票"表。

## 4. 增量缓存机制

### 4.1 数据库结构（SQLite）

- **stocks 表**：代码、名称、行业、更新时间
- **financial_reports 表**：联合主键 `(ts_code, report_date, report_type)`，每条记录对应一个报告期，存储所有解析指标及 `last_update`

### 4.2 缓存有效期（含披露截止日保护）

- **年报**：超过 400 天且已过次年 4 月 30 日 → 需更新；否则暂不更新
- **季报/半年报**：超过 100 天 → 需更新

### 4.3 每日运行流程

1. 加载股票列表，连接 DB
2. 判断每只股票是否需要刷新（`should_refresh`）
3. 不需刷新：从缓存组合数据；需刷新：并发获取，批量写入 DB
4. 合并，行业分类，统计，评分，生成报告

## 6. 命令行用法

```bash
python stock_analyzer_v3.9.py --base-dir ./workplace --stock-file xuan.txt --workers 8 --delay 0.8
```

**主要参数：**

| 参数 | 说明 |
|---|---|
| `--base-dir` | 工作目录（默认脚本所在目录） |
| `--stock-file` | 股票列表文件 |
| `--workers` | 线程数（默认 8） |
| `--delay` | 提交间隔秒（默认 1.0，可适当降低提速） |
| `--force-refresh` | 忽略缓存全量更新 |
| `--timeout` | 全局超时秒（默认 3600，0 不限） |
| `--industry-map-url` | 在线行业映射 URL |
| `--no-retry-failed` | 禁止失败补采 |
| `--no-industry-patch` | 禁止行业 API 补调 |
| `--test` | 运行内置自测 |

## 7. 关键配置常量（可修改 Config 类）

| 参数 | 默认值 | 说明 |
|---|:---:|---|
| `FINANCE_WORKERS` | 8 | 并发数 |
| `GLOBAL_DELAY` | 1.0 | 提交间隔（秒） |
| `API_TIMEOUT` | 50s | 单次 API 超时 |
| `CACHE_MAX_AGE_ANNUAL` | 400天 | 年报有效期（结合披露日） |
| `CACHE_MAX_AGE_QUARTERLY` | 100天 | 季报有效期 |
| `ANNUAL_DISCLOSURE_DEADLINE_MONTH` | 4 | 年报截止月 |
| `ANNUAL_DISCLOSURE_DEADLINE_DAY` | 30 | 年报截止日 |
| `MIN_INDUSTRY_SAMPLES` | 5 | 行业最少样本 |
| `MARKET_FALLBACK_DISCOUNT` | 0.95 | 全市场折扣 |
| `LOW_COMPLETENESS_PENALTY` | 0.9 | 低完整度折扣 |
| `LOG_MAX_BYTES` | 10MB | 日志轮转大小 |

## 8. 注意事项

- 首次全量获取约需十几分钟，后续每日运行仅更新少数股票，数分钟内完成。
- 若 API 大面积返回空，系统自动暂停后重试，异常均记录在日志和 Excel 中。
- 内置行业映射表为手工整理，可能有个别偏差，可通过 online URL 或外部文件更新。
- 低置信度股票建议人工复核。
- 日志使用 `RotatingFileHandler`，确保长期运行不会无限增长。
