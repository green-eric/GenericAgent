# 业绩分析系统 V5.0.0 逻辑文档

## 1. 版本概述

**核心目标**：基于 NeoData 真实 API 数据，对 A 股年报进行结构化段落匹配与业绩评分。

**V5 核心变更**：
- 完全移除 V4 的正则切分（`_split`/`_classify`/`latest`）流程，改为**直接段落匹配**策略
- 通过 `"统计截止日期为YYYY1231的年报"` 精确锚定年报段落，从根本上杜绝 Q1/Q3/年报数据混淆
- API 调用改为 `requests` 直连（`https://copilot.tencent.com/agenttool/v1/neodata`），不再通过 subprocess 调用 query.py 脚本
- 使用 `requests.Session` + `HTTPAdapter` 连接池复用，提升高并发下的网络效率
- 查询语句简化为 `{ts_code} {name} 年报`，避免因关键词过多导致搜索失败
- 净利润提取增加特殊逻辑：找以"净利润"开头且不含"归母"/"扣非"的行
- 新增内置自测模式（`--test`），验证段落提取与指标解析正确性

---

## 2. 整体流程

```
加载股票列表 → 缓存检查 → 并发获取 → 段落定位 → 逐行匹配 → 行业归类 → 评分计算 → 报告输出
```

| 步骤 | 说明 |
|------|------|
| **加载股票列表** | 从 `xuan.txt` 读取代码和名称，滤除北交所/科创板等不关注的板块（688/430/83/87 开头） |
| **缓存检查** | 对每只股票判断本地 SQLite 缓存中的年报是否过期 |
| **并发获取** | 使用 `requests.Session` 连接池，多线程并发调用 NeoData API |
| **段落定位** | 用 `"统计截止日期为YYYY1231的年报"` 精确锚定年报段落，跳过 Q1/Q3 等单季报 |
| **逐行匹配** | 在年报段落内按关键词逐行搜索，提取 13 个财务指标 |
| **行业归类** | 多级策略确定申万一级行业（文本解析 → 本地映射 → 名称规则 → API 补调 → 代码前缀） |
| **评分计算** | 基于年报指标，在同行业内进行百分位评分，生成四维评分和综合评级 |
| **报告输出** | 输出 Excel 综合评价报告、JSON 明细数据、异常日志 |

## 3. 数据获取与缓存策略

### 3.1 API 调用方式

直接通过 `requests` 库 HTTP POST 调用 NeoData API：

```
POST https://copilot.tencent.com/agenttool/v1/neodata
Authorization: Bearer {token}
```

Token 从 `~/.workbuddy/.neodata_token` 文件读取。

### 3.2 查询构建

对每只股票发送精简查询：

```
{ts_code} {name} 年报
```

> ⚠️ V5 刻意简化了查询语句。V4 曾使用"年报 主要财务指标 利润表 现金流量表 资产负债表"等多关键词，但实践中发现关键词过多反而导致 NeoData 搜索命中率下降。

API 返回一整段可能包含多年、多期报告的长文本（含 Q1、年报、Q4 等段落混合）。

### 3.3 缓存判断（`should_refresh`）

缓存数据库中至少需要有一条 `annual` 类型的记录，否则直接刷新。

**年报过期条件**（满足任一即刷新）：

- 当前日期已超过 **年报年份 + 1 年** 的 **4 月 30 日**（强制刷新，确保拿到新年报）
- 距离报告日期的天数 > `CACHE_MAX_AGE_ANNUAL`（默认 **400 天**）

### 3.4 缓存读取（`merge_latest_reports`）

从数据库取出最新的那条 `annual` 记录，与 `stocks` 表中的名称、行业合并，组装成评分所需的字典结构。**不再涉及季报/半年报**。

## 4. 年报解析（V5 核心：直接段落匹配）

### 4.1 段落定位（`_extract_annual_block`）

**不再使用正则切分全文**。改为精确匹配锚点：

```python
统计截止日期为(\d{4})1231的年报
```

- 从锚点位置开始，到下一个 `"统计截止日期为"` 或文本结束为止
- 保证提取到的段落只包含年报数据，Q1/Q3 等单季报被天然隔离

**兜底策略**：若未找到年报锚点，尝试从业绩趋势段落推断日期（`_guess_date_from_trend`），返回空指标。

### 4.2 逐行匹配（`_extract_metric_line`）

在定位到的年报段落内，按关键词列表逐行搜索，返回第一个匹配行的完整文本。

### 4.3 指标提取（`parse_financial_all`）

共提取 **13 个指标**：

| 类别 | 指标 | 关键词 | 提取方式 |
|------|------|--------|---------|
| **盈利能力** | ROE | 加权净资产收益率ROE / 净资产收益率ROE / 加权净资产收益率 | 百分比 |
| | 毛利率 | 销售毛利率 | 百分比（从"毛利率"后取，避免一行多百分比取错） |
| | 净利率 | 销售净利率 | 百分比（从"净利率"后取） |
| **成长性** | 营收同比 | 营业收入同比增长 / 营收同比增长 / 营业总收入同比增长 | 同比增长率 |
| | 净利润同比 | 归母净利润同比增长 | 同比增长率 |
| **偿债风险** | 资产负债率 | 资产负债率 | 百分比 |
| **规模与现金流** | 营业总收入 | 营业总收入 / 营业收入 | 带单位数值（亿/万/万亿） |
| | 净利润 | 净利润（不含归母/扣非） | 带单位数值（特殊逻辑） |
| | 扣非净利润 | 扣非净利润 | 带单位数值 |
| | 经营现金流净额 | 经营活动产生的现金流量净额 | 带单位数值 |
| **现金流质量** | 经营现金流/净利润 | — | 计算值（OCF ÷ 净利润） |
| **运营效率** | 总资产周转率 | 总资产周转率 | 次数（如 0.85次） |
| | 应收账款周转率 | 应收账款周转率 | 次数 |

> ⚠️ **净利润提取特殊逻辑**：遍历年报段落每一行，找到以 `"净利润"` 开头但**不含** `"归母"`、`"扣非"`、`"现金含量"`、`"增长率"`、`"同比"` 的行。这避免了将"归母净利润"、"扣非净利润"、"净利润现金含量"、"净利润增长率"等衍生指标误识别为"净利润"。

## 5. 行业归属确定流程

对每只股票，按以下**优先级**尝试确定申万一级行业：

1. **文本解析**：从年报内容中匹配"所属一级行业"等关键词（`extract_industry_from_content`）
2. **本地映射表**：根据股票代码查询 `industry_map.json`（或内置 100 条兜底表 `_FALLBACK_INDUSTRY_MAP`）
3. **二级行业映射**：若有二级行业，通过 `SECONDARY_TO_PRIMARY` 表转为一级
4. **名称规则**：通过 `NAME_KEYWORD_INDUSTRY` 表从股票名称推断
5. **API 补调**（可选）：针对仍未分类的股票，调用 NeoData API 查询行业（分批执行，每批 100 只，批间休眠 1s，使用 15 线程 + Session 连接池）
6. **代码前缀规则**：最终仍未分类的，用 `CODE_PREFIX_INDUSTRY` 猜测

所有分类结果写入数据库的 `stocks` 表，下次可复用。

## 6. 评分体系（严格基于年报）

### 6.1 指标维度与权重

| 维度 | 权重 | 子指标及权重 |
|------|------|-------------|
| **盈利能力** | 35% | ROE（40%）、毛利率（30%）、净利率（30%） |
| **成长性** | 30% | 营收同比（40%）、净利润同比（60%） |
| **现金流质量** | 15% | 经营现金流/净利润 |
| **偿债风险** | 20% | 资产负债率 |

### 6.2 评分方法

- 对每项指标，在同行业内进行百分位排名，转化为 **0~100** 分值
- 若行业样本不足 **5** 只（`MIN_INDUSTRY_SAMPLES`），退化为全市场百分位，并乘以 **0.95** 折扣（降低置信度）
- ROE 为负值直接给 **0** 分
- 净利润与经营现金流均为负且净利润为负时，总分上限锁定为 **15** 分

### 6.3 完整度惩罚

统计 **7** 项核心指标的非空数量，计算完整度比例：

| 完整度 | 条件 | 惩罚 |
|--------|------|------|
| **高** | ≥ 70% | 无惩罚 |
| **中** | ≥ 40% | 无惩罚 |
| **低** | < 40% | 总分 × 0.9 |
| **极低** | ≤ 1 项 | 在低的基础上再 × 0.75 |

### 6.4 评级与置信度

| 总分 | 评级 |
|------|------|
| ≥ 75 | **A** |
| ≥ 55 | **B** |
| ≥ 40 | **C** |
| ≥ 25 | **D** |
| < 25 | **E** |

**置信度** = 完整度等级（高 / 中 / 低）

## 8. 并发与限流策略

### 8.1 并发架构

- 使用 `ThreadPoolExecutor`（默认 **16 线程**）并发获取财务数据
- 共享 `requests.Session` + `HTTPAdapter` 连接池（`pool_connections` = `pool_maxsize` = workers）
- HTTPAdapter 内置重试（财务数据获取 `max_retries=2`，行业补调 `max_retries=1`）

### 8.2 限流保护

- **连续 API 错误**（网络/超时）达到 **10** 次时，暂停 **20 秒**后重置计数器
- **正常但无数据**（新股/退市等）不计入连续错误，不触发暂停
- 全局超时（`GLOBAL_TIMEOUT` = **7200s**）后取消剩余任务

### 8.3 行业补调分批

- 每批最多 **100** 只，批间休眠 **1s** 避免触发 API 限流
- 使用 **15 线程** + `requests.Session` 连接池（`max_retries=1`）
- 单只超时上限 **60s**
- API 失败后降级为名称推断（`infer_industry_from_name`）

### 8.4 进度日志

每处理 **100** 只股票输出一次进度，包含：
- 已处理数 / 总数
- 当前速率（只/秒）
- 已用时间 / 预估剩余时间
- API 错误计数

## 9. 自测模式

运行 `python stock_analyzer.py --test` 可启动内置自测：

- 使用模拟 NeoData 返回格式（含 Q1 + 年报 + Q4 三段混合，含"净利润现金含量"等衍生指标）
- 验证 `_extract_annual_block()` 正确排除 Q1/Q4，只提取年报段落
- 验证 `parse_financial_all()` 所有 13 个指标解析正确
- **关键验证**：净利润必须从 `"净利润1642130865.33元"` 提取，而非 `"净利润现金含量160.44%"`
- 输出逐项断言结果，确保段落匹配逻辑无误

## 13. 注意事项

> ⚠️ 系统严格依赖年报数据，若某股票未披露任何年报，将直接评为低完整度、低分，需人工关注。

> 📅 年报过期判断中的 **4 月 30 日**截止日可根据市场实际情况调整（`ANNUAL_DISCLOSURE_DEADLINE_MONTH` / `ANNUAL_DISCLOSURE_DEADLINE_DAY`）。

> 📊 行业内评分要求至少 **5** 只股票，小行业可能触发全市场基准，评分可能偏低。

> 🔧 NeoData Token 需放置在 `~/.workbuddy/.neodata_token` 文件中。

> 🔧 V5 查询语句已简化为 `{ts_code} {name} 年报`。如需调整查询策略，修改 `fetch_stock_finance()` 中的 `query` 变量。
