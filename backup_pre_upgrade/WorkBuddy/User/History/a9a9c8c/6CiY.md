# 业绩分析系统 V4.0.0 逻辑文档

## 1. 版本概述

**核心目标**：彻底统一评分数据来源为最新年报，移除所有季报/半年报逻辑，解决原先指标来源混乱（有时取年报、有时取季报）的问题，并简化失败重试机制。

---

## 2. 整体流程

```
加载股票列表 → 缓存检查 → 并发获取 → 文本解析 → 行业归类 → 评分计算 → 报告输出
```

| 步骤 | 说明 |
|------|------|
| **加载股票列表** | 从 `xuan.txt` 读取代码和名称，滤除北交所/科创板等不关注的板块 |
| **缓存检查** | 对每只股票判断是否需要重新获取年报数据（依据本地 SQLite 缓存） |
| **并发获取** | 对需要刷新的股票，调用外部 API 批量拉取年报文本 |
| **文本解析** | 从 API 返回的多期报告混合文本中，严格提取最新一段年报的财务指标 |
| **行业归类** | 优先从年报文本、本地映射表、名称规则、API 补调等多级策略确定申万一级行业 |
| **评分计算** | 基于年报指标，在同行业内进行百分位评分，生成四维评分和综合评级 |
| **报告输出** | 输出 Excel 综合评价报告、JSON 明细数据、异常日志 |

---

## 3. 数据获取与缓存策略

### 3.1 查询构建

对每只股票发送查询：

```
{ts_code} {name} 年报 主要财务指标 利润表 现金流量表 资产负债表
```

API 返回一整段可能包含多年、多期报告的长文本。

### 3.2 缓存判断（`should_refresh`）

缓存数据库中至少需要有一条 `annual` 类型的记录，否则直接刷新。

**年报过期条件**（满足任一即刷新）：

- 当前日期已超过 **年报年份 + 1 年** 的 **4 月 30 日**（强制刷新，确保拿到新年报）
- 距离报告日期的天数 > `CACHE_MAX_AGE_ANNUAL`（默认 **400 天**）

### 3.3 缓存读取（`merge_latest_reports`）

从数据库取出最新的那条 `annual` 记录，与 `stocks` 表中的名称、行业合并，组装成评分所需的字典结构。**不再涉及季报/半年报**。

---

## 4. 文本解析与年报提纯（核心变更）

### 4.1 段落切分（`_split`）

使用增强正则切分文本：

```
(\d{4}[-/年]?(?:\d{1,2}[-/月]?\d{1,2}[日号]?)?)
```

支持"2024年度"、"2024年年报"等无具体月日的标题，将其标准化日期为 `YYYY1231`。

每个段落包含：

| 字段 | 说明 |
|------|------|
| `date` | 标准化日期 |
| `content` | 该段文本 |
| `type` | 分类 |

### 4.2 类型分类（`_classify`）

仅识别一类：

- **`annual`**：包含"年报"、"年度报告"、"全年"关键词

其余所有段落（含季报、半年报、未知）均归为 `unknown`，**不参与任何提取**。

### 4.3 选取最新年报

`latest("annual")`：从所有 `annual` 段落中取日期最新的一个。

### 4.4 指标提取（`extract`）

仅对上述选出的年报段落进行正则提取，共 **13 个指标**：

| 类别 | 指标 |
|------|------|
| **盈利能力** | ROE、毛利率、净利率 |
| **成长性** | 营收同比、净利润同比 |
| **偿债风险** | 资产负债率 |
| **规模与现金流** | 营业总收入、净利润、扣非净利润、经营现金流净额（含单位换算） |
| **现金流质量** | 经营现金流/净利润（计算值） |
| **运营效率** | 总资产周转率、应收账款周转率 |

> ⚠️ **关键变更**：移除了原先的全局 fallback 提取，杜绝了因年报缺失某项指标而随意从整个文本中补取值，从而混入季报数据的可能。

## 5. 行业归属确定流程

对每只股票，按以下**优先级**尝试确定申万一级行业：

1. **文本解析**：从年报内容中匹配"所属一级行业"等关键词
2. **本地映射表**：根据股票代码查询 `industry_map.json`（或内置 100 条兜底表）
3. **二级行业映射**：若有二级行业，尝试通过 `SECONDARY_TO_PRIMARY` 表转为一级
4. **名称规则**：通过 `NAME_KEYWORD_INDUSTRY` 表从股票名称推断
5. **API 补调**（可选）：针对仍未分类的股票，单独调用行业查询 API
6. **代码前缀规则**：最终仍未分类的，用 `CODE_PREFIX_INDUSTRY` 猜测

所有分类结果写入数据库的 `stocks` 表，下次可复用。

## 6. 评分体系（严格基于年报）

### 6.1 指标维度与权重

| 维度 | 权重 | 子指标及权重 |
|------|------|-------------|
| **盈利能力** | 35% | ROE（40%）、毛利率（30%）、净利率（30%） |
| **成长性** | 30% | 营收同比（40%）、净利润同比（60%） |
| **现金流质量** | 15% | 经营现金流/净利润 |
| **偿债风险** | 20% | 资产负债率 |

### 6.2 评分方法

- 对每项指标，在同行业内进行百分位排名，转化为 **0~100** 分值
- 若行业样本不足 **5** 只（`MIN_INDUSTRY_SAMPLES`），退化为全市场百分位，并乘以 **0.95** 折扣（降低置信度）
- ROE 为负值直接给 **0** 分
- 净利润与经营现金流均为负且净利润为负时，总分上限锁定为 **15** 分

### 6.3 完整度惩罚

统计 **7** 项核心指标的非空数量，计算完整度比例：

| 完整度 | 条件 | 惩罚 |
|--------|------|------|
| **高** | ≥ 70% | 无惩罚 |
| **中** | ≥ 40% | 无惩罚 |
| **低** | < 40% | 总分 × 0.9 |
| **极低** | ≤ 1 项 | 在低的基础上再 × 0.75 |

### 6.4 评级与置信度

| 总分 | 评级 |
|------|------|
| ≥ 75 | **A** |
| ≥ 55 | **B** |
| ≥ 40 | **C** |
| ≥ 25 | **D** |
| < 25 | **E** |

**置信度** = 完整度等级（高 / 中 / 低）

## 7. 数据库结构

### `stocks` 表

| 字段 | 类型 | 说明 |
|------|------|------|
| `ts_code` | PK | 股票代码 |
| `name` | | 股票名称 |
| `industry_l1` | | 申万一级行业 |
| `industry_l2` | | 申万二级行业 |
| `last_industry_update` | | 行业最后更新时间 |
| `last_full_update` | | 完整数据最后更新时间 |

### `financial_reports` 表

| 字段 | 说明 |
|------|------|
| `ts_code` | 股票代码 |
| `report_date` | 报告日期 |
| `report_type` | 报告类型（实际只使用 `annual`） |
| 所有年报指标字段 | — |

> **唯一约束**：`(ts_code, report_date, report_type)`

---

## 8. 并发与异常处理

- 使用 `ThreadPoolExecutor`（默认 **8 线程**）并发获取财务数据
- 全局超时（`GLOBAL_TIMEOUT`）后取消剩余任务并记录
- 连续出现 **5** 次空数据暂停 **30** 秒，防止 API 限流
- ⚠️ **已移除失败重试机制**：不再对首轮失败的股票进行单独重试

## 11. 注意事项

> ⚠️ 系统严格依赖年报数据，若某股票未披露任何年报，将直接评为低完整度、低分，需人工关注。

> 📅 年报过期判断中的 **4 月 30 日**截止日可根据市场实际情况调整。

> 📊 行业内评分要求至少 **5** 只股票，小行业可能触发全市场基准，评分可能偏低。
