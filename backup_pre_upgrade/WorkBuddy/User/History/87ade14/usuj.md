# A股智能选股系统 - 基于季报+年报的业绩评分系统 版本: 7.0.0

## 项目概述

基于 A 股上市公司**季报+年报**数据，通过多维度财务指标评分模型，对股票进行综合业绩评级。系统采用 **NeoData API** 获取真实季报文本，结合 **akshare 申万一级行业分类**实现精准行业定位，最终输出带评级与置信度的 Excel 分析报告。

**核心特性：**
- 数据来源真实可靠（NeoData API 实时季报，拒绝模拟数据）
- 行业分类权威（akshare 申万一级行业，31个行业全覆盖）
- 评分模型多维（盈利能力、成长性、现金流质量、偿债风险）
- 置信度评估（8项核心指标完整度，自动折扣低质量数据）
- **TTM计算引擎（近4季度滚动计算关键指标）**
- **单季看成长，TTM看盈利与现金，最新报表看杠杆**

> **V7.0.0重大升级**: 相比V6.0.0，移除了年报ROE兜底逻辑，所有盈利能力指标均基于TTM数据，评分更前瞻、更准确。

## 数据架构策略

### V7.0.0 新特性：单季看成长，TTM看盈利与现金，最新报表看杠杆

| 评估维度 | 数据源 | 计算方式 | 说明 |
|----------|--------|----------|------|
| **成长性** | 最新单季报 | 营收同比、净利润同比 | 前瞻性指标，反映最新增长动能 |
| **盈利能力** | TTM | ROE_TTM、毛利率_TTM、净利率_TTM | 近4季度滚动，平滑季节性波动 |
| **偿债风险** | 最新单季报 | 资产负债率 | 时点数据，衡量当前财务杠杆 |
| **现金流质量** | TTM | OCF/净利润_TTM | 利润现金兑现能力，TTM加权计算 |
| **绝对值** | TTM | 净利润_TTM、经营现金流_TTM | 近4季度总和，反映真实经营规模 |

> **TTM计算逻辑**: `ROE_TTM = 净利润TTM ÷ 最新季度净资产 × 100`
> **净利润TTM** = Q1净利润 + Q2净利润 + Q3净利润 + Q4净利润
>
> **V7.0.0关键改进**: 严格使用TTM数据，移除年报ROE兜底逻辑，确保所有盈利能力指标基于最新经营成果，评分更前瞻、更准确。

## 行业判定策略（6级混合优先级）

`determine_industry()` 采用逐级回退策略，确保行业判定覆盖率最大化：

| 优先级 | 数据源 | 说明 | 耗时 |
|--------|--------|------|------|
| **1** | 季报原文提取 | 公司自己披露的行业信息，最准确 | 即时 |
| **2** | akshare 申万一级行业 | 权威分类，4880+只股票100%覆盖，本地JSON缓存30天 | 首次~3分钟，后续<1秒 |
| **3** | 股票名称关键词推断 | 基于名称关键词（如"银行"→银行、"医药"→医药生物） | 即时 |
| **4** | NeoData API 查询 | 大模型实时查询，补漏用 | 单只~2秒 |
| **5** | 本地静态映射表 | `industry_map.json`，历史遗留数据 | 即时 |
| **6** | 代码前缀兜底 | 60→机械设备, 00→房地产, 30→医药生物, 68→电子 | 即时 |

> **注意：** akshare 提供的是**申万一级行业**（31个），非二级行业（131个）。选择一级的原因：覆盖率100%、同行业池足够大（避免<5只触发全市场折扣）、稳定性好。

### akshare 行业缓存机制

- 缓存文件：`industry_map_akshare.json`
- 有效期：30天（`AKSHARE_CACHE_MAX_AGE_DAYS = 30`）
- 首次构建：遍历31个申万一级行业成分股，约3分钟
- 后续运行：直接读缓存，<1秒
- 强制刷新：`--force-refresh`

## 评分模型

### 四维评分权重

| 维度 | 权重 | 子指标 | 说明 |
|------|------|--------|------|
| **盈利能力** | 40% | ROE×0.4 + 毛利率×0.3 + 净利率×0.3 | 衡量公司赚钱效率 |
| **成长性** | 30% | 营收同比×0.4 + 净利润同比×0.6 | 衡量增长动能 |
| **现金流质量** | 20% | OCF/净利润 | 利润的现金兑现能力 |
| **偿债风险** | 10% | 资产负债率（反向） | 负债越低得分越高 |

### 评分计算流程

```
原始指标 → 百分位排名(0~100) → 子维度加权 → 行业/全市场折扣 → 完整度折扣 → 亏损惩罚 → 总分
```

#### 百分位排名

在同行业池（或全市场池）中，计算该股票某指标的排名百分位：

```python
# 正向指标（值越大越好）：ROE、毛利率、净利率、营收同比、净利润同比、OCF/净利润
percentile = (池中 ≤ 该值的股票数 / 池总股票数) × 100

# 反向指标（值越小越好）：资产负债率
percentile = (池中 > 该值的股票数 / 池总股票数) × 100
```

#### 参考池选择规则

```
同行业池股票数 ≥ 5 → 使用同行业池（无折扣）
同行业池股票数 < 5 → 回退全市场池 × 0.95折扣
```

#### 数据完整度折扣

系统跟踪 **7个核心指标**：ROE(TTM)、毛利率(TTM)、净利率(TTM)、营收同比(单季)、净利润同比(单季)、资产负债率(单季)、OCF/净利润(TTM)

| 完整度 | 条件 | 折扣 |
|--------|------|------|
| 高置信度 | ≥ 6/7 项有值（≥85.7%） | ×1.0（无折扣） |
| 中置信度 | ≥ 4/7 项有值（≥57.1%） | ×1.0（无折扣） |
| 低置信度 | 2~3/7 项有值 | ×0.9 |
| 极低置信度 | ≤ 1/7 项有值 | ×0.9 × 0.75 = ×0.675 |

> **V7.0改进**: 相比V6.0，移除了年报ROE兜底，所有盈利能力指标均基于TTM数据，评分更前瞻

#### 亏损惩罚

当 **TTM净利润 < 0 且 TTM经营现金流 < 0** 时，总分上限为 15 分。

### 评级标准

| 评级 | 总分范围 | 含义 | Excel颜色 |
|------|---------|------|-----------|
| **A** | ≥75分 | 优秀 | 🟢 绿色 |
| **B** | 55~74分 | 良好 | 🟢 浅绿 |
| **C** | 40~54分 | 一般 | 🟡 黄色 |
| **D** | 25~39分 | 较差 | 🟠 浅红 |
| **E** | <25分 | 很差 | 🔴 红色 |

## 财务指标提取

从 NeoData API 返回的季报文本中，系统自动提取以下指标：

| 指标 | 提取关键词 | 单位 | 数据源 |
|------|-----------|------|--------|
| ROE | 加权净资产收益率ROE / 净资产收益率ROE | % | **TTM** |
| 毛利率 | 销售毛利率 | % | **TTM** |
| 净利率 | 销售净利率 | % | **TTM** |
| 营收同比 | 营业收入同比增长 / 营收同比增长 | % | **最新单季** |
| 净利润同比 | **归母净利润同比增长** | % | **最新单季** |
| 资产负债率 | 资产负债率 | % | **最新单季** |
| **净利润** | `^归母净利润`（严格行首匹配，排除同比/扣非） | 元 | **TTM** |
| 经营现金流 | 经营活动产生的现金流量净额 | 元 | **TTM** |

> **关键设计：** 
> - 净利润严格取"归母净利润"（归属母公司股东的净利润），而非合并报表的"净利润"（含少数股东损益），确保与东方财富等主流平台口径一致
> - **V7.0.0改进**: 所有盈利能力指标均基于TTM计算，移除年报ROE兜底逻辑，评分更反映最新经营成果

### 季报段落提取

系统通过锚点精确定位季报数据段落：

1. **主锚点：** `统计截止日期为{year}(0331|0630|0930)的季报`
2. **过滤未来年份：** 自动排除大于当前年份的"季报"
3. **TTM计算：** 提取最近4个季度数据，自动计算滚动指标
4. **兜底策略：** 无锚点时，提取含关键词（营业收入、净利润、ROE等）的行

## 快速开始

### 环境要求

- Python 3.7+
- 操作系统：Windows / macOS / Linux
- 内存：建议 ≥4GB
- 磁盘空间：≥500MB（含缓存数据库）

### 安装依赖

```bash
pip install -r requirements.txt
```

依赖列表：`requests`, `openpyxl`, `akshare`

### 配置 Token

1. 在用户目录下创建 `.workbuddy` 文件夹：
```bash
mkdir -p ~/.workbuddy
```

2. 在该文件夹下创建 `.neodata_token` 文件，填入 API Token：
```
your_api_token_here
```

### 准备股票列表

在项目目录下创建 `xuan.txt` 文件，每行一只股票：

```
600000 浦发银行
000001 平安银行
600036 招商银行
```

支持格式：
- 纯代码（自动补全 `.SH` / `.SZ` 后缀）
- 代码 + 名称（空格/逗号/制表符分隔）

**自动过滤：** 科创板（688开头）和北交所（430/83/87开头）股票自动跳过。

### 运行程序

```bash
# 基本运行
python qa_scorer.py

# 指定股票文件
python qa_scorer.py --stock-file xuan.txt

# 强制刷新（清空缓存，重新获取季报 + 重建行业映射）
python qa_scorer.py --force-refresh

# 调整并发线程数
python qa_scorer.py --workers 8

# 禁用 NeoData API 补全（仅用本地数据判定行业）
python qa_scorer.py --no-industry-patch

# 运行基础测试
python qa_scorer.py --test
```

### 命令行参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--base-dir` | str | 当前目录 | 工作目录 |
| `--stock-file` | str | xuan.txt | 股票列表文件路径 |
| `--workers` | int | 4 | 并发线程数（默认4，可根据API限流情况调整） |
| `--force-refresh` | flag | False | 忽略缓存，全量更新 |
| `--no-industry-patch` | flag | False | 禁用 NeoData API 行业补全 |
| `--timeout` | int | 7200 | 全局超时（秒） |
| `--test` | flag | False | 运行基础测试后退出 |

## 常见问题

**Q: Token 文件在哪里？**
`~/.workbuddy/.neodata_token`

**Q: 如何清除缓存？**
删除 `quarterly_cache.db` 和 `industry_map_akshare.json`，或使用 `--force-refresh`

**Q: 支持哪些股票市场？**
上交所（.SH）和深交所（.SZ）主板。科创板（688）和北交所（430/83/87）自动过滤。

**Q: 净利润为什么用"归母净利润"而非"净利润"？**
合并报表的"净利润"包含少数股东损益，口径偏大。归母净利润反映母公司股东实际可分配利润，与东方财富等主流平台一致。

**Q: 行业判定用的是申万一级还是二级？**
**一级行业**（31个）。一级覆盖率高（100%）、行业池大（避免<5只触发折扣），适合横向比较。

**Q: 数据获取失败怎么办？**
1. 检查 Token 是否正确
2. 查看日志文件定位具体错误
3. 减少并发线程数 `--workers 2`（默认已为4，API限流严重时可降至2）

**Q: TTM计算有什么特点？**
- ROE_TTM = 净利润TTM ÷ 最新季度净资产 × 100
- 净利润TTM = 最近4个季度净利润之和
- 净资产取最新季度的时点数（不是TTM累加）
- **V7.0.0改进**: 严格使用TTM数据，移除年报ROE兜底逻辑，评分更前瞻

> **数据策略**: "单季看成长，TTM看盈利与现金，最新报表看杠杆" - 这种架构既保持前瞻性又不失稳定性
