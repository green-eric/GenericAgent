## 核心依赖关系

### 1. 数据共享
- **stock_cache.db**: 两个项目共用同一个SQLite数据库
  - `financial_reports` 表: 存储年报和季度财务数据
  - `stocks` 表: 存储股票代码、名称和行业信息
- **xuan.txt**: 相同的股票列表文件（4,344只A股）

### 2. API接口
- **NeoData Token**: 两个项目都使用 `~/.workbuddy/.neodata_token`
- **API Endpoint**: 相同的 NeoData API 地址
- **查询格式**: 年报用 `{ts_code} {name} 年报`，季报从年报文本中提取季度段落

## 功能定位差异

### 年报项目 (V5.0.0)
**核心任务**: 基于年报数据的年度选股分析
- **数据来源**: 直接从 NeoData API 获取年报全文
- **指标提取**: 13个核心财务指标（ROE、毛利率、净利率、营收同比、利润同比等）
- **评分体系**: 4D评分（盈利35%+成长30%+现金流15%+负债20%）
- **行业处理**: 多级行业归类策略（文本解析→本地映射→名称规则→API补调→代码前缀）
- **输出格式**: Excel报告（8个Sheet）+ JSON明细数据

### 季报项目 (V6.0.0)
**核心任务**: 基于季度数据的补充评分分析
- **数据来源**: 从年报文本中提取最新季度段落
- **指标提取**: 季度特有指标（毛利率、净利率、营收同比、利润同比）
- **评分体系**: 继承年报框架，季度指标覆盖对应字段
- **交叉验证**: 年报A级 ∩ 季报A级 = 优选股票
- **输出格式**: Excel报告（3个Sheet）+ JSON交叉验证报告

## 工作流程整合

### 完整分析流程
```
1. 年报项目运行
   ↓ (生成 stock_cache.db 和 industry 数据)
2. 季报项目运行
   ↓ (读取缓存，获取季度数据，计算季度评分)
3. 交叉验证分析
   ↓ (年报A∩季报A = 优选股票)
```

### 数据流转
1. **初始阶段**: 年报项目获取并缓存所有股票的年报数据
2. **补充阶段**: 季报项目从缓存读取年报数据，并发获取季度数据
3. **验证阶段**: 两个项目的评分结果进行交叉验证

## 技术优势

### 季报项目的创新点
1. **数据复用**: 充分利用年报项目的缓存数据，避免重复API调用
2. **交叉验证**: 引入年报和季报的双重验证机制，提高选股准确性
3. **动态更新**: 季度数据提供更及时的业绩反馈
4. **优选机制**: 年报A∩季报A形成高确定性投资池

### 系统协同效应
- **减少API调用**: 季报项目主要依赖年报缓存，大幅降低API负载
- **一致性保证**: 两个项目使用相同的评分体系和行业分类标准
- **效率提升**: 季报项目可以更快完成分析（专注于季度数据处理）

3. **行业轮动**: 基于季度评分的行业表现分析
4. **量化回测**: 将优选机制用于历史数据回测验证
