## 二、架构评估

### 2.1 数据流架构 ✅ 优秀

```
AkShare API → DataProvider(多源降级) → SQLite → Calculator → Scorer → Excel
```

**优点：**
- 获取-评分解耦：支持 `--fetch-only` → `--from-db` 两阶段模式
- 三级降级链：全市场行情缓存 → 东方财富个股 → NeoData兜底
- 断点续传：自动跳过已有 ≥4 季度的股票
- 增量更新：区分全量获取 vs 增量更新

**建议改进：**
- `utils_cache.py`（DataCache）与 `database.py`（StockDatabase）功能重叠，建议明确分工或合并
- `batch_runner.py`（BatchRunner）与 `main.py` 内置的并发逻辑重复，建议统一

### 2.2 模块职责

| 模块 | 职责 | 行数 | 评估 |

## 五、代码质量评估

### 5.1 优点

1. **防未来函数**：`ann_date` 公告日过滤，支持 `--date` 历史回测
2. **单季拆分**：完全向量化（零iterrows），性能优秀
3. **熔断机制**：`_akshare_unavailable` 和 `_financial_api_failed` 防止雪崩
4. **并发安全**：线程锁 + 信号量限流
5. **Excel输出**：维度分组着色、条件格式、评级颜色
6. **数据完整度**：`get_completeness_info()` 季度覆盖率 + 关键字段缺失检查
7. **银行股特殊处理**：毛利率为0时不再误算100%
8. **扣非净利润优先**：`net_profit_ex` 存在时优先使用

### 5.2 代码问题

#### 🔴 严重问题

1. **版本号不一致**
   - `main.py` 标注 `v3.1.2`
   - 记忆文件记录 `V6.0.0`
   - 建议：统一版本号

2. **数据库数据严重不足**
   - 仅24只股票有数据（stock_pool.txt 仅24行，不是4344行）
   - 行情记录为0
   - 建议：全量获取数据

#### 🟡 中等问题

3. **`main.py` 过长**（1284行）
   - 建议：将 `from-db` 评分逻辑、`fetch-only` 逻辑、`save_to_excel` 拆分为独立模块

4. **模块功能重叠**
   - `utils_cache.py` vs `database.py`
   - `batch_runner.py` vs `main.py` 内置并发
   - 建议：明确分工或合并

5. **`_mock_evaluate` 返回 `name: symbol`**（第269行）
   - 模拟模式下股票名称返回代码本身，与真实模式不一致
   - 应返回 `name` 变量

6. **`main()` 中 `from-db` 模式的全局变量污染**
   - `_market_failed`、`_market_preloaded` 通过 `main` 函数对象设置属性
   - 建议：封装为类或传入参数

7. **估值权重偏低**（10%）
   - PE-TTM 阈值20，A股中位数约25-30
   - 大部分股票估值得分为0或很低

#### 🟢 轻微问题

8. **缺少单元测试**
   - 无 `tests/` 目录
   - 建议：添加 calculator 和 scorer 的单元测试

9. **缺少类型提示**
   - 部分函数缺少返回类型注解
   - 建议：补充 `->` 类型提示

10. **日志级别不一致**
    - 部分关键操作为 `debug` 级别，生产环境看不到
    - 建议：关键路径用 `info`

## 六、性能评估

2. **行情记录为0** → 每次评分都需实时获取行情
3. **stock_pool.txt 仅24行** → 不是真正的全市场扫描

## 十二、总结

ScoreSys 是一个**架构合理、代码质量良好**的 A股量化选股系统。核心亮点包括：

- ✅ 完善的五维评分 + 一票否决机制
- ✅ 防未来函数设计（公告日过滤）
- ✅ 多数据源自动降级 + 熔断保护
- ✅ 高性能计算（向量化，5x提速）
- ✅ 详尽的中文注释和文档

主要短板在于**数据严重不足**（仅24只股票有数据）和**模块功能重叠**。建议优先解决数据获取问题，然后进行代码重构。

**综合评级：B+（74.5/100）**
