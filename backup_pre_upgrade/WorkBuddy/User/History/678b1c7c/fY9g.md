# 字段取值逻辑验证报告

## 根本原因

API返回的文本结构是：每个子段落以"根据...在A股市场YYYYMMDD发布的财报数据，统计截止日期为YYYYMMDD的Qx单季报/年报"开头。

**关键发现**：
1. **单季报中只有"归母净利润同比增长"，没有"营业收入同比增长"**
2. **年报中同时有"营业收入同比增长"和"归母净利润同比增长"**
3. 旧代码用"统计截止日期为YYYYMMDD的..."作为锚点拆block，导致多个子段落被合并到一个block中

## 各字段正确取值逻辑

| 字段 | 数据来源 | 取值逻辑 |
|------|---------|---------|
| **revenue_yoy** (营收同比) | 最新单季报 → 最新年报 | 优先从最新单季报取，没有则从最新年报取（API单季报无营收同比，实际总是从年报取） |
| **profit_yoy** (净利润同比) | 最新单季报 → 最新年报 | 优先从最新单季报取，没有则从最新年报取 |
| **debt_ratio** (资产负债率) | 最新单季报 | 从最新单季报的资产合计和负债合计计算 |
| **total_assets** (资产合计) | 最新单季报 | 直接从最新单季报取 |
| **total_liabilities** (负债合计) | 最新单季报 | 直接从最新单季报取 |
| **roe_ttm** | TTM计算 | 近4个季度净利润之和 / 最新单季净资产 |
| **gross_margin_ttm** | TTM计算 | (营收TTM - 成本TTM) / 营收TTM × 100 |
| **net_margin_ttm** | TTM计算 | 净利润TTM / 营收TTM × 100 |
| **ocf_ratio_ttm** | TTM计算 | OCF_TTM / 净利润TTM × 100 |
| **revenue_ttm** | TTM计算 | 近4个季度营业总收入之和 |
| **net_profit_ttm** | TTM计算 | 近4个季度归母净利润之和 |
