### 1. 年报数据库共享

**共享文件**: `AnnualScorer/stock_cache.db`

| 表 | 字段 | 用途 | 共享方式 |
|----|------|------|----------|
| `stocks` | `industry_l1` | 申万一级行业 | 直接读取 |

```python
Config.ANNUAL_DB_FILE = os.path.join(os.path.dirname(BASE_DIR), "AnnualScorer", "stock_cache.db")
```

### 2. 行业映射共享

**共享文件**: `industry_map_akshare.json`

- **季报项目**: 自动生成并读取
- **年报项目**: 同样使用相同文件
- **缓存机制**: 30天有效期，避免重复获取

### 3. 股票代码列表共享

**共享文件**: `xuan.txt`

- **格式**: `代码 名称` (空格分隔)
- **自动过滤**: 科创板(688)、北交所(430/83/87)自动跳过
- **后缀补全**: 自动添加.SH/.SZ后缀

## 🎯 核心差异点

### 1. 数据时效性策略

| 维度 | 季报项目 V7.0.0 | 年报项目 V6.0.0 |
|------|----------------|----------------|
| **成长性** | 最新单季报同比 | 年报同比 |
| **盈利能力** | TTM (近4季度) | 年报 |
| **现金流质量** | TTM OCF/净利润 | 年报 OCF/净利润 |
| **偿债风险** | 最新单季资产负债率 | 年报资产负债率 |
| **绝对值** | TTM净利润/OCF | 年报净利润/OCF |

### 2. TTM计算引擎 (V7.0.0新特性)

```
TTM ROE = 净利润TTM / 最新季度净资产 × 100
其中：
- 净利润TTM = Q1净利润 + Q2净利润 + Q3净利润 + Q4净利润
- 净资产 = 最新季度的净资产数据（时点数）
```

**存储结构**:
- `quarterly_reports`: 原始季度数据 (168条记录)
- `quarterly_ttm_cache`: TTM计算结果 (28条记录)

### 3. 评分模型一致性

✅ **完全一致**:
- 四维权重: 盈利40% + 成长30% + 现金流20% + 风险10%
- 百分位排名算法
- 置信度评估标准
- 评级标准 (A-E)
- 亏损惩罚机制

### 4. 行业判定策略

✅ **完全一致**:
- 6级混合优先级
- akshare申万一级行业
- 本地静态映射表
- 代码前缀兜底

## 🔄 协同工作流程

### 1. 数据流协同

```
年报项目年度运行
    ↓
生成 stock_cache.db (含年报数据)
    ↓
季报项目启动
    ↓
读取 stock_cache.db (年报数据)
    ↓
获取最新季报数据
    ↓
计算TTM指标
    ↓
合并年报+季报数据
    ↓
评分输出
```

### 2. 时间节奏配合

| 时间 | 年报项目 | 季报项目 |
|------|----------|----------|
| **1月-3月** | 上年年报已出 | 可使用上年年报 |
| **4月** | 本年年报陆续发布 | 开始获取本年年报 |
| **5月-10月** | 本年年报基本齐全 | 主要使用本年年报 |
| **11月-12月** | - | 获取最新季报，计算TTM |

### 3. 数据互补优势

**年报项目优势**:
- 数据最完整准确
- 适合长期投资分析
- 财务数据权威性高

**季报项目优势**:
- 数据更及时
- 前瞻性更强
- TTM指标反映近期趋势

**协同价值**:
- 年报提供基准数据
- 季报提供动态更新
- TTM平滑季度波动

## 🛠️ 维护建议

### 1. 数据库管理

**年报数据库 (`stock_cache.db`)**
- 定期备份 (建议每月)
- 清理过期年报数据
- 监控文件大小增长

**季报数据库 (`quarterly_cache.db`)**
- 自动清理过期缓存 (30天)
- 监控TTM计算成功率
- 处理缺失净资产数据的股票

### 2. 版本升级策略

**季报项目 V7.0.0 升级要点**:
- ✅ 已实现TTM计算引擎
- ✅ 移除年报ROE兜底逻辑
- ✅ 严格使用TTM数据
- ⚠️ 需要监控缺少净资产数据的股票

**未来升级方向**:
- 增加季度间数据一致性检查
- 优化TTM计算性能
- 增加异常数据处理机制

### 3. 故障排查指南

**常见问题**:

1. **API调用失败**
   - 检查Token有效性
   - 降低并发线程数 `--workers 2`

2. **TTM计算失败**
   - 检查净资产数据完整性
   - 验证季度数据连续性

3. **行业判定失败**
   - 检查akshare缓存是否过期
   - 使用 `--force-refresh` 重建
