# A股智能选股分析系统 V3.7 逻辑文档

## 1. 系统概述

本系统通过 NeoData 自然语言金融数据 API 获取 A 股最新财务报告，自动解析关键指标与行业分类，基于行业内百分位评分生成 A~E 五级评级，输出 Excel 报告和 JSON 数据。

### V3.7 核心特性

- **统一目录管理**：所有文件（输入、输出、数据库、日志）均在同一文件夹
- **输出文件名自动加上时间戳**，防止覆盖
- **SQLite 缓存增量更新**：首次全部获取，以后每天仅更新过期或缺失的股票
- **财务数据按报告期（年报/一季报/半年报/三季报）存储**，并记录报告期日期
- **行业分类采用多级兜底策略**，覆盖率 >95%
- **数据获取异常自动记录到 Excel 的"异常日志"工作表**

## 2. 系统架构与数据流

```
股票列表文件 -> 主程序 -> 加载配置与数据库
                           |
                     [SQLite 缓存]
                           |
                     需要更新？
                   /          \
         是（从API获取）   否（从缓存加载）
                   \          /
                    合并全部数据
                           |
                    行业分类补全
                           |
                    构建行业统计
                           |
                    计算评分与评级
                           |
                    生成 Excel 报告和 JSON
```

## 3. 核心模块说明

### 3.1 配置管理 (Config类)

所有参数集中管理，支持命令行修改，包括：
- 文件路径、并发线程数、API超时与重试设置
- 缓存有效期（年报400天，季报100天）
- 评分权重、完整度阈值、惩罚系数

### 3.2 API调用 (run_neodata)

- 调用 NeoData 查询脚本，自动指数退避重试
- 自动处理可能的输出干扰和JSON解析错误

### 3.3 文本解析器 (FinancialReportParser)

- 按日期分割返回文本，识别年报、季报、半年报段落
- 提取百分比（ROE、毛利率等）和绝对值（营收、净利润等）
- 自动识别数值单位（万、亿、万亿）并换算成元
- 返回报告日期和类型，用于缓存时间判断

### 3.4 行业分类引擎（多级顺序）

| 优先级 | 策略             | 说明 |
|--------|------------------|------|
| 1      | 文本提取         | API返回内容中直接提取 |
| 2      | 内置/外部映射表   | 约3000+条内置映射，或外部 industry_map.json |
| 3      | 二级→一级反查     | 通过二级行业名称反推一级行业 |
| 4      | 名称关键词推断     | 股票简称中的行业词（如"医药"、"银行"） |
| 5      | 轻量API补调       | 对仍未分类的股票发起简洁查询 |
| 6      | 代码前缀推断       | 仅兜底使用（如600→银行） |

### 3.5 评分模型

#### (1) 百分位计算
- 有明确行业且样本充足（≥5只）：按行业内百分位
- 行业样本不足或未分类：使用全市场百分位，得分乘以0.95

#### (2) 四维加权评分
```
盈利能力 = 0.4×ROE百分位 + 0.3×毛利率百分位 + 0.3×净利率百分位
成长性   = 0.4×营收同比百分位 + 0.6×净利润同比百分位
现金流   = 经营现金流/净利润百分位
偿债风险 = 资产负债率百分位（越低越好）
总评分 = 0.35×盈利 + 0.30×成长 + 0.15×现金流 + 0.20×偿债
```

#### (3) 特殊惩罚
- 净利润<0 且 经营现金流净额<0 → 总分最高15分

#### (4) 数据完整度处理
- 缺失7项核心指标中的多项：分为高/中/低三级完整度
- 低完整度：总分乘以0.9，且最高评级不超过C级

#### (5) 评级线
- ≥75分: A级
- ≥55分: B级
- ≥40分: C级
- ≥25分: D级
- 其余: E级

### 3.6 异常日志

全局记录所有数据获取、解析、行业补调等环节的失败详情，最终写入Excel的"异常日志"工作表。

## 4. 增量缓存机制

### 4.1 数据库结构 (SQLite)

**stocks表**：股票代码、名称、行业、更新时间

**financial_reports表**：
- 联合主键 (ts_code, report_date, report_type)
- 每条记录对应一个具体报告期（如 20251231 年报）
- 存储所有解析出的财务指标，以及 last_update 字段

### 4.2 缓存有效期判断

- 年报：报告期距今超过400天 → 需更新
- 季报/半年报：报告期距今超过100天 → 需更新
- 行业：若缓存有效且不为"未分类"，基本视为永久；否则可能重新获取

### 4.3 每日运行流程

1. 加载股票列表，连接数据库
2. 逐一判断每只股票是否需要刷新（should_refresh）
3. 不需刷新：从缓存组合数据（merge_latest_reports）
   需要刷新：加入待获取队列，并发调用API获取新数据，并存入数据库
4. 合并所有数据（缓存 + 新获取）
5. 进入行业分类、统计、评分、报告生成流程

## 5. 文件目录结构（--base-dir 指定的工作目录）

```
stock_workplace/
├── stock_analyzer_v3.7.py      # 主程序
├── xuan.txt                    # 股票列表（代码+名称）
├── industry_map.json           # （可选）外部行业映射
├── stock_cache.db              # SQLite 缓存数据库（自动生成）
├── stock_analyzer_*.log        # 运行日志（含时间戳）
├── 股票业绩评价_*.xlsx          # 分析报告（含时间戳）
└── 股票分析数据_*.json         # JSON 原始数据（含时间戳）
```

## 6. 命令行用法

```bash
python stock_analyzer_v3.7.py --base-dir ./workplace --stock-file xuan.txt --workers 6
```

### 主要参数

- `--base-dir`：工作目录（默认为脚本所在目录）
- `--stock-file`：股票列表文件名（相对或绝对路径）
- `--workers`：并发线程数（默认8）
- `--force-refresh`：忽略缓存，全量重新获取
- `--no-retry-failed`：禁止失败重试补采
- `--no-industry-patch`：禁止行业API补调

## 7. 关键配置常量（可在 Config 类中修改）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| FINANCE_WORKERS | 8 | 财务数据并发数 |
| API_TIMEOUT | 50秒 | 单次API超时 |
| GLOBAL_DELAY | 1.2秒 | 每只股票提交间隔 |
| CACHE_MAX_AGE_ANNUAL | 400天 | 年报缓存有效期 |
| CACHE_MAX_AGE_QUARTERLY | 100天 | 季报缓存有效期 |
| MIN_INDUSTRY_SAMPLES | 5 | 行业内最少股票数 |
| MARKET_FALLBACK_DISCOUNT | 0.95 | 全市场评分折扣 |
| LOW_COMPLETENESS_PENALTY | 0.9 | 低完整度评分折扣 |
| MAX_RATING_LOW_COMPLETENESS | C | 低完整度最高评级 |

## 8. 注意事项

- 财报披露时间有限制，缓存有效期已尽量贴合实际发布节奏。
- API若频繁返回空，系统会自动暂停后重试，所有异常均记录在日志和Excel中。
- 内置行业映射表为手工整理，可能存在少量偏差，建议定期用外部 industry_map.json 更新。
- 数据完整度低的股票评分可信度较差，建议人工复核。
