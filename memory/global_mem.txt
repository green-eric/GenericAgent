## [微信代码泄露修复] (2026-05-05)
- 问题: LLM生成的Python代码片段通过微信回复泄露给用户
- 根因: _clean() 逐行正则只匹配特定关键词开头(import/url/req/print)，
  遗漏变量赋值类代码行(如 html = urllib.request.urlopen(req).read())
- 修复: _clean() 完全重写为5阶段过滤
  Phase1: 删除大块结构(code blocks ```...```、inline code、JSON tool results、=== markers)
  Phase2: 删除工具调用行(🛠️/🔧/调用工具/args)
  Phase3: 删除内部标记(LLM Running/⏳/✅/━)
  Phase4: 宽泛代码模式匹配20+种(import/from/def/class/if/for/while/try/except/
        var=func()/obj.method()/print()/赋值语句等)，循环5次确保嵌套清除
  Phase5: 格式清理(空行压缩+markdown strip)
- 验证: 3种泄露场景(直接嵌入代码/JSON块/多轮对话)全部通过
- git: c4554b0
- 关键教训: 过滤代码不能用"关键词黑名单"思路，必须用"大块删除+宽泛模式+多轮迭代"

## [微信Bot 统一格式化 _fmt_wx] (2026-05-05)
|- 核心问题：微信纯文本不渲染 \n 换行和 Markdown（**粗体**、## 标题等）
|- 错误做法：每个功能单独调格式 → 永远改不完
|- 正确做法：在 send_text() 出口统一处理
|- 改动1: 新增 _fmt_wx() 函数（frontends/wechatapp.py ~line 268）
  - 去 Markdown 符号（**粗体**→纯文本、`代码`→纯文本、~~删除线~~→纯文本）
  - 表格 → 列表形式
  - \n → \u2028（微信唯一有效换行符）
|- 改动2: send_text() 内部加 text = _fmt_wx(text)，所有调用点自动生效
|- 改动3: _strip_md() 改为 _fmt_wx() 的 wrapper（向后兼容）
|- 快速通道天气查询仍用 \u2028 手动拼，经 _fmt_wx 后无破坏性影响
|- 未实测：需要在微信端实际发送消息验证换行效果
|- 教训：不要在 send_text 之前预处理，要在 send_text 内部统一处理
